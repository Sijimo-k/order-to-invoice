# Order to Invoice

A Google Apps Script for a Google Sheet that turns shop orders into paid invoices:

1. **Import orders** from Shopify (or any JSON in the Shopify orders shape) into an Orders sheet. Running it again updates rows instead of adding duplicates.
2. **Create PDF invoices** from a Google Docs template you can restyle freely. Invoice numbers run per year (`INV-2026-0001`) and are never reused.
3. **Email the invoices** with the PDF attached. **Test mode is on by default**: every email goes to you, with the intended customer in the subject.
4. **Track payments.** Tick *Paid* and the payment date and status fill in. Unpaid invoices turn *Overdue* after the due date, and one click sends reminders.
5. **See the month** in a Summary sheet: orders, sales, invoiced, paid, outstanding and overdue.
6. **Run it daily** with one menu item (import, invoice, send).

It ships with ten fictional orders built in, so you can try every step without a store or any keys.

## Try it

1. Create a Google Sheet, then **Extensions > Apps Script**.
2. Copy the files from [`src/`](src) into the editor (or use [clasp](https://github.com/google/clasp): `clasp create --type sheets --rootDir src`, then `clasp push`).
3. Reload the sheet. In the new **Order to Invoice** menu, run **Set up (first time)** and allow the permissions.
4. Run **Import orders**, then **Create invoices**, then **Send invoices**. With test mode on, the emails arrive in your own inbox.

Set up creates the sheets, an editable invoice template in Google Docs and a Drive folder for the PDFs.

## Use your own shop

- **Shopify**: put `your-store.myshopify.com` in *Settings > Shopify store*, and add a custom app's Admin API token as the script property `SHOPIFY_TOKEN` (*Project Settings > Script properties*). Orders are read page by page through the Admin REST API.
- **Anything else**: point *Settings > Orders URL* at a URL that returns `{ "orders": [...] }` in the Shopify shape.
- Untick *Test mode* only when you are ready to email real customers.

## How it is built

| Part | File |
|---|---|
| Pure logic: order mapping, money in integer cents, invoice numbers, due dates, statuses, email text, monthly summary | [`src/Core.js`](src/Core.js) |
| Menu, one-click setup, settings, invoice template | [`src/Setup.js`](src/Setup.js) |
| Import from Shopify or a URL, Orders and Line items sheets | [`src/Orders.js`](src/Orders.js) |
| PDF invoices from the Docs template, emails, reminders | [`src/Invoices.js`](src/Invoices.js) |
| Paid checkbox, statuses, Summary sheet, daily trigger | [`src/Payments.js`](src/Payments.js) |

Details that matter in real use:

- **No float errors**: amounts are kept in cents; `$52.60` stays `$52.60`.
- **Totals are checked**: if subtotal − discount + shipping + tax does not match the shop's total, the row gets a note instead of a silently wrong invoice.
- **Dates do not drift**: due dates are calendar days in the sheet's time zone.
- **Safe to run twice**: imports update in place, invoices and emails are never created twice, and a lock stops two runs from overlapping.
- **Edits are respected**: invoices are built from the sheet, so a corrected amount in the sheet is what the customer sees.

## Tests

```bash
npm install
npm test
```

`test/core.test.js` covers the logic. `test/gas-smoke.test.js` runs the whole flow (set up, import, invoice, email in test mode, mark paid) against small in-memory fakes of the Google services.

## Demo data

`demo/orders.json` and `src/DemoData.js` are fictional, generated by `tools/make-demo-orders.mjs`. All names and addresses are made up and every email uses `example.com`.
